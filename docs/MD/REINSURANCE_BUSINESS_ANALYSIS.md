# 再保险公司业务流程分析 - 系统需求梳理

## 🎯 核心问题：这个系统到底要解决什么？

作为**再保险公司**，你们面临的核心挑战是：

### ❓ 关键业务问题

**场景1：承保决策**
```
问题：某家香港直保公司想买你们的再保险
      他们提交了1000栋建筑的数据
      
你需要回答：
❓ 这些建筑在哪里？
❓ 有多少在高风险区域（比如海边低洼地带）？
❓ 如果发生百年一遇的洪水，我们可能赔多少钱？
❓ 这个价格（保费）合理吗？风险可接受吗？
```

**场景2：组合管理**
```
问题：你们已经承保了10个分出公司的业务
      覆盖香港、澳门、新加坡等地区
      
你需要回答：
❓ 我们在香港地区总共承保了多少资产？
❓ 如果香港发生超强台风+暴雨，最大可能损失是多少？
❓ 我们的风险是否过于集中？
❓ 需要购买临分再保险吗（Retrocession）？
```

**场景3：灾害响应**
```
问题：2024年9月香港发生了严重洪水
      
你需要回答：
❓ 哪些承保的建筑受影响？
❓ 预计理赔金额是多少？
❓ 哪些分出公司会提出索赔？
❓ 我们的准备金够吗？
```

**场景4：业务分析**
```
问题：年底要做投资组合分析报告
      
你需要回答：
❓ 各地区的风险暴露度（Exposure）是多少？
❓ 哪些地区风险最高？
❓ 保费收入 vs 预期损失 的比例合理吗？
❓ 明年的承保策略应该调整吗？
```

## 🔍 当前系统的三个模块

让我们看看现有的三个模块分别做什么：

### 1. 灾害信息库（Disaster Repository）✅ 已完成

**作用**：存储历史灾害和模拟灾害事件

```
例如：
- 历史事件：2023年台风Mangkhut、2022年6月暴雨
- 模拟事件：200年一遇洪水、500年一遇台风

用途：
✓ 研究历史灾害特征
✓ 使用灾害数据评估风险
✓ 情景分析（What-if scenarios）
```

**核心功能**：
- ✅ 灾害事件的上传、存储、查看
- ✅ 按类型、时间、地区筛选
- ✅ 地图可视化
- ✅ 数据导出

---

### 2. 风险地图（Risk Map）- 现有模块

**作用**：显示地理区域的风险等级

```
例如：
- 香港哪些区域是洪水高危区？
- 澳门低洼地带的风险评分是多少？

用途：
✓ 快速识别高风险区域
✓ 承保决策参考
✓ 资产风险评估
```

**可能的数据来源**：
- 政府发布的洪水风险图
- 历史灾害统计
- 地形数据（高程、坡度）
- 排水系统数据

## 💡 资产管理模块的定位

### 选项A：承保组合管理（Portfolio Management）

**核心功能**：管理你们承保的所有资产

```
主要用户：承保经理、精算师、风险管理团队

核心问题：
1️⃣ 我们承保了哪些资产？
   - 分出公司A：香港500栋建筑
   - 分出公司B：澳门200栋建筑
   - 分出公司C：新加坡300栋建筑

2️⃣ 这些资产的风险如何？
   - 地图上显示所有资产位置
   - 按风险等级标色
   - 识别风险集中区域

3️⃣ 风险暴露度（Exposure）分析
   - 总保额：$100亿
   - 高风险区域保额：$30亿
   - 单一事件最大损失（PML）：$5亿

4️⃣ 组合优化
   - 风险是否过于集中？
   - 需要调整承保策略？
```

**界面功能**：
```
左侧：筛选面板
├── 按分出公司筛选
├── 按地区筛选
├── 按风险等级筛选
├── 按保额范围筛选
└── 按建筑类型筛选

中间：地图显示
├── 所有资产的位置标记
├── 按风险等级颜色编码
├── 热力图显示风险密度
└── 点击查看资产详情

右侧：统计面板
├── 总资产数量
├── 总保额
├── 风险分布
├── PML估算
└── 按地区/类型统计
```

---

### 选项B：新业务评估（New Business Evaluation）

**核心功能**：评估新的承保申请

```
主要用户：承保经理

业务流程：
1. 分出公司提交承保申请
2. 上传资产数据（Excel/CSV）
3. 系统自动分析风险
4. 生成承保建议报告

核心问题：
❓ 这批资产的风险等级如何？
❓ 有多少在高风险区域？
❓ 预期损失率是多少？
❓ 建议承保价格（费率）？
❓ 是否接受这个业务？
```

**界面功能**：
```
工作流：
1. 上传新业务数据
   └─> Excel/CSV文件

2. 自动风险分析
   ├── 地理位置风险评分
   ├── 与历史灾害叠加分析
   ├── 与风险地图对比
   └── 计算PML

3. 生成评估报告
   ├── 风险概览
   ├── 高风险资产列表
   ├── PML曲线
   ├── 定价建议
   └── 承保决策建议

4. 决策
   └─> 接受 / 调整条件 / 拒绝
```

---

### 选项C：灾害损失评估（Catastrophe Loss Estimation）

**核心功能**：模拟灾害事件的损失

```
主要用户：精算师、风险管理

场景：
"如果明天香港发生500年一遇的洪水，
 我们承保的资产会损失多少？"

核心问题：
❓ 哪些资产会受影响？
❓ 预计损失金额？
❓ 哪些分出公司会提出索赔？
❓ 我们的准备金够吗？
```

**界面功能**：
```
工作流：
1. 选择灾害情景
   ├── 使用历史事件
   ├── 使用模拟事件
   └── 自定义情景

2. 分析影响范围
   └─> 地图显示受影响资产

3. 计算损失
   ├── 按资产类型
   ├── 按地区
   └── 按分出公司

4. 生成报告
   ├── 损失明细
   ├── 理赔预测
   └── 财务影响
```

我建议把三个模块理解为一个**完整的风险管理流程**：

```
┌──────────────────────────────────────────────────────────┐
│                 再保险风险管理系统                          │
└──────────────────────────────────────────────────────────┘

1️⃣ 【灾害信息库】- 基础数据层 ✅
   ↓
   提供历史灾害和模拟情景
   
2️⃣ 【风险地图】- 风险评估层
   ↓
   显示哪些地方风险高
   
3️⃣ 【资产管理】- 业务应用层 ← 这里需要明确
   ↓
   将风险评估应用到实际业务
```

主要功能：

   ├── 导入分出公司数据

   ├── 地图显示所有资产
   ├── 风险等级标色
   └── 与风险地图叠加

3. 暴露度分析
   ├── 总保额统计

   ├── 按风险等级分布

4. 情景分析 (简化版)
   ├── 选择一个灾害事件

## 🤔 帮你决策：三个关键问题

### Q1: 你们公司目前最迫切的需求是什么？

**A. 需要管理现有的承保组合**
   → 选择"组合管理"方案
   → 重点：可视化、统计分析

**B. 需要评估新的业务机会**
   → 选择"新业务评估"方案
   → 重点：快速风险分析、定价建议

**C. 需要做灾害情景分析**
   → 选择"损失评估"方案
   → 重点：情景模拟、损失计算

---

### Q2: 谁会使用这个模块？

**承保经理（Underwriter）**：
- 需要快速评估业务风险
- 需要可视化展示
- 需要简单的统计数据

**精算师（Actuary）**：
- 需要详细的数据分析
- 需要PML计算
- 需要导出数据做进一步分析

**风险管理（Risk Manager）**：
- 需要组合风险概览
- 需要识别风险集中
- 需要情景分析
